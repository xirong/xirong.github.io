# 太阳系与银河系：真实三维效果实施方案

更新日期：2026-11-06。

建议继续使用 **Three.js 负责网页中的实时光照、三维空间与交互，Blender 负责需要专门制作的模型和贴图资产**。先把地球、土星和银河侧视的效果做好，再接入正式页面。普通球体可以由 Three.js 直接建立，无需把所有行星在 Blender 中重新做一遍。

本目录是一份独立效果演示。入口为 [index.html](index.html)，实现为 [preview.js](preview.js)。演示复用已有纹理和 Three.js 库，不替换正式太阳系、银河系页面，也不更新 App 或安装包。本文中的“代码可见”只表示实现已经写入本地文件，不能代替浏览器运行、手机实机或正式上线验收。

## 本轮演示的实际验证

2026-11-06，使用 Playwright MCP 在本机浏览器完成以下检查：

- 桌面 1440×900 检查地球、土星、木星、太阳系全景和银河多视角，保留实际画面截图。全景能显示八颗行星名称。
- 鼠标拖动、滚轮缩放、全景点击木星后飞近、暂停、复位和说明弹窗均通过。暂停后模拟时间和地球转角保持不变；飞行中拖动接管后恢复正常缩放范围。
- 390×844、320×740、844×390、375×568 视口检查无横向溢出，主要控制区在首屏内，顶部按钮不重叠。这是浏览器视口验证。
- 分别阻断地球贴图、土星 GLB、银河来源图，均显示失败提示并结束加载状态；取消阻断后点击重新加载均恢复。模拟 WebGL 上下文丢失也显示失败提示。
- 正常资源加载未出现失败请求，浏览器 Console 无错误或警告；JavaScript 语法检查与 Git 空白检查通过。

**未验证：**真实手机上的单指、双指操作和持续性能；Safari / App 内核；完整三维尘埃遮光和连续跨尺度飞行。本机浏览器的 CDP 触摸注入接口返回 `Not allowed`，因此不把鼠标和视口检查冒充为触摸验收。下文的完整验收表是正式实施要求，不能据本节推断已全部完成。

交互还包含鼠标拖动、滚轮缩放、触摸控制、镜头过渡、加载状态、失败反馈和减少动态效果偏好。银河在首次切换时才构建。当前代码为桌面与窄屏设置不同像素比和粒子数量，但这只是初步控制开销，还没有形成按观察距离切换细节的完整方案，也不能据此声称手机已流畅运行。

## “真实”具体指什么

行星应采用来源明确的纹理，再用正确的光照和球体空间关系呈现。当前使用的 [Solar System Scope 贴图](https://www.solarsystemscope.com/textures/) 以 NASA 数据为基础，按 CC BY 4.0 授权。来源说明同时指出部分未测绘区域有补绘、色彩有增强。因此适合称为“基于观测数据制作的贴图”，不能把每张都称为未经加工的真实照片。正式资产清单应记录作者、许可、处理方式和对应文件。

银河外部全貌需要标为模型。NASA 的[银河结构图](https://science.nasa.gov/photojournal/our-milky-way-gets-a-makeover-artist-concept/)明确属于艺术重建，依据观测解释中央棒状结构、旋臂和太阳所在的猎户支臂。这张图发布于 2008 年，能说明证据性质，不代表全部细节都是当前精确测量。本演示实际读取仓库的 `textures/milkyway.jpg`，其来源和署名记录在 [textures/README.md](../textures/README.md)，页面也保留对应素材链接。

[ESA Gaia 全天图](https://www.esa.int/media/gaia-s-sky-in-colour-en-210002)汇总从太阳系附近看到的各个天空方向的恒星亮度与颜色。它可以用于适当视角的星空背景，但单张全天投影没有提供完整银河的三维深度。将来若引入 Gaia 测量数据，应单独处理距离质量、误差与覆盖范围，不能把图片上的亮点直接当作已测量的三维位置。

太阳位置标记可以放大以便寻找，但需要持续说明“标记放大、方位示意”。银河画面中的颗粒也应说明代表星光分布，避免让孩子误以为看到的每个点都恰好是一颗已经定位的恒星。

## Blender 放在哪一环最合适

建议采用以下分工：

1. **Blender 制作资产。**处理土星环、探测器、不规则小行星、地形与剖面等需要编辑形状或整理贴图的对象；统一尺度、原点、朝向、材质和模型复杂度，导出适合网页加载的 GLB。
2. **Three.js 实时呈现。**负责阳光方向、昼夜、阴影、云层运动、大气近似、模型选择、相机过渡和手机操作。
3. **科学数据与说明独立管理。**形状、颜色、尺度、自转、公转和说明文字应能追溯来源，避免为了让画面好看而悄悄改变科学含义。

Blender 中的电影级渲染不能自动等价为网页效果。[官方 glTF 手册](https://docs.blender.org/manual/en/4.5/addons/import_export/scene_gltf2.html)说明导出器只识别一定的材质节点组合；复杂节点、体积散射和合成结果不会完整搬运。手册中的体积导出主要是吸收与透射材质，不是通用的烟雾、星云体积渲染通道。

现有 [Three.js r128 GLTFLoader 源码](https://raw.githubusercontent.com/mrdoob/three.js/r128/examples/js/loaders/GLTFLoader.js)包含透射扩展处理，但没有内置 `KHR_materials_volume` 处理器。不能承诺“Blender 中做出体积银河，导出一个 GLB，网页就原样呈现”。需要把适合烘焙的部分转换为贴图，其余部分在网页中按预算实现并验证。

当前演示保持 r128。若正式方案需要升级渲染器，应作为明确的兼容性改造处理：同步检查加载器、控制器、材质、颜色输出和已有场景，不混用新旧版本接口。

## 正式接入分三个阶段

### 阶段一：形成可复用的视觉内核

**产物：**可接入两张正式页面的行星与银河渲染模块、资产来源清单、场景验收记录。

- 把演示中的真实纹理、昼夜、大气、云层和薄环整理为可复用模块。明确每类天体采用哪些效果，无大气天体不套用地球光晕。
- 统一太阳方向、材质颜色、曝光和阴影。先保证明暗与遮挡，再评估少量辉光。[Three.js 后期处理文档](https://threejs.org/manual/pages/post-processing.html)说明辉光等效果作用于已渲染图像，不能替代正确的三维结构；实际实现需要使用与 r128 匹配的代码。
- 为银河建立能从不同方向观察的盘、核球和棒状结构。若要让侧视出现可信的尘埃遮光，需要增加真正参与遮挡或衰减的空间模型，并说明简化方式。
- 接入点选与平滑飞近时，保留正式页面既有导航和知识入口，核对拖动、点击与触摸的行为。旁白继续沿用项目已有音频方案，不把演示中缺少旁白视为正式功能完成。

### 阶段二：完成分层加载与性能控制

**产物：**按场景和距离加载的资源方案、不同设备画质档位、实际设备的加载和性能记录，以及失败恢复行为。

- 先加载当前观察所需的纹理和模型，接近时再补高分辨率资源；切离场景时管理缓存与显存释放。
- 加入 LOD，即按观察距离切换细节。近处保留球面与环细节，远处采用更简单的表示。可参考 [Three.js LOD 文档](https://threejs.org/docs/pages/LOD.html)，并以 r128 的实际接口为准。
- 按实测决定像素比、阴影分辨率、银河粒子数量和透明层数量。粒子很多时，重叠透明像素也会消耗性能，不能只看模型面数。
- 在指定桌面和真实手机上记录首屏等待、切换等待、帧时间与内存变化，再确定可接受预算。当前不虚构工期、帧率或资源上限。
- 补齐资源失败、慢网、图形上下文中断和再次加载的行为，确保用户知道发生了什么，也有恢复入口。

### 阶段三：按需求选择跨尺度与测量数据

**可选产物：**太阳系至恒星邻域、再至银河的连续观察流程，或者带测量来源与误差说明的局部恒星视图。

连续跨尺度会影响坐标精度、相机目标、资源加载和尺度表达，应在前两阶段稳定后决定是否加入。需要明确哪些区间采用真实比例，哪些为了可见性压缩距离或放大天体，不能只靠一次长距离相机移动掩盖比例变化。

测量数据适合先用于覆盖可靠的太阳邻域。保留观测日期、坐标系、距离误差与筛选条件；银河整体仍可采用有依据的结构模型。引入数据不自动等于整个银河都已被精确复原。

## 验收看什么

以下是正式验收标准，尚不表示这些检查已经全部通过。运行证据应记录设备、视口、操作步骤，以及截图或测量结果。

| 检查 | 通过的依据 |
| --- | --- |
| 地球昼夜 | 暂停后绕到正面、侧面和背面观察；明暗边界与太阳方向一致，夜间灯光不会在白昼同等发亮，大气边缘不会在背光面整圈泛蓝。 |
| 中间视角 | 连续拖动并检查四分之一转、半转等位置。遮挡随空间关系变化，云层、球体与环没有穿插、翻面或突然跳层。不能只检查预设视角截图。 |
| 土星薄环 | 从上方、斜侧和接近环平面观察，环逐渐收窄；检查球体遮住后方环带、投在环上的影子，以及环投在球体上的影子。透明区域不能被错误画成实心圆盘。 |
| 银河侧视 | 侧面仍能看见银盘厚度和中央隆起；转回俯视后结构连续。当前演示的尘埃仅为暗纹，不把它计为三维遮光验收通过。正式增加尘埃后要检查它对后方星光的影响。 |
| 桌面与手机操作 | 鼠标拖动和滚轮、手机单指旋转和双指缩放都能完成观察；点选与拖动不混淆；按钮不遮挡主要对象；可复位，暂停后天体运动停止且仍可调整观察角度。 |
| 镜头过渡 | 从总览进入每颗行星，检查起点、中途和终点；相机不穿入球体或环，运动中对象仍可理解；用户拖动后能接管视角。 |
| 加载失败 | 分别模拟纹理、GLB 和银河来源图加载失败，以及图形环境中断。页面不无限显示加载动画或只留下黑屏，应提供清楚反馈和恢复操作。 |
| 科学表达 | 素材来源、模型性质、比例压缩、运动加速和太阳标记放大可被找到。孩子能从操作中发现昼夜、薄环和银河厚度，而不是只看到装饰效果。 |
| 正式接入回归 | 检查两张正式页面原有入口、知识展示和旁白；如改动共享渲染模块，检查受影响的已有行星页面。App 与安装包是后续正式发布范围，独立演示不声称已经更新它们。 |

本轮演示用于决定视觉方向。正式实施前，真正需要确定的是优先改善哪些场景、目标手机与画质要求，以及是否需要第三阶段；这些选择会改变后续产物和验收范围。
